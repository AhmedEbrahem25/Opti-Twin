# FAEA — Frontend AI Experience Architecture
## MASTER ORCHESTRATION MODULE
**Version:** 2.0 | **Scope:** Universal | **Role:** System controller

---

## WHAT THIS SYSTEM IS

FAEA is a **modular AI prompting framework** for building cinematic, award-quality frontend experiences.  
It is not a single prompt. It is a **composable operating system** — load only the modules you need, in the order defined here.

Each module has a single responsibility. No module duplicates logic from another. The orchestrator (this file) defines how they interact.

## INITIALIZATION ORDER (JavaScript)

This is the **absolute execution sequence**. Never deviate.

```
1. GSAP config + plugin registration          [ANIMATION]
2. Custom eases                               [ANIMATION]
3. Lenis init (before any scroll logic)       [SCROLL]
4. Interactive background init                [BACKGROUND]
5. Loading sequence → onComplete callback     [INTRO]
   5a. Cinematic intro sequence               [INTRO]
   5b. Bind intro exit (CTA click)            [INTRO]
6. window.initMainExperience() — post-CTA:
   6a. Navbar init + entrance animation       [NAVBAR]
   6b. Barba page transitions                 [SCROLL]
   6c. Scroll reveal + parallax               [ANIMATION]
   6d. Desktop-only:
       — CinematicCursor                      [CURSOR]
       — ThreeEngine                          [WEBGL]
       — Tilt cards                           [INTERACTIONS]
       — Magnetic nav                         [INTERACTIONS]
   6e. AdaptiveQuality (wraps ThreeEngine)    [PERFORMANCE]
   6f. FPSMonitor (localhost only)            [PERFORMANCE]
   6g. ScrollTrigger.refresh() after 100ms    [ANIMATION]
```

## PRIORITY HIERARCHY

When modules conflict (e.g., MODES overrides TOKENS defaults):

```
1. PERFORMANCE constraints      ← Highest. FPS < 30 forces downgrades.
2. PROJECT MODE settings        ← Override TOKENS + ANIMATION defaults.
3. IDENTITY aesthetic rules     ← Override individual component decisions.
4. TOKENS values                ← Override any hardcoded values.
5. Module-level defaults        ← Lowest. Used when nothing above applies.
```

```
All except WEBGL (unless 3D is needed for the concept)
```

## CONFLICT PREVENTION RULES

| Conflict | Rule |
|---|---|
| Multiple RAF loops | Only one — GSAP ticker owns all. No `requestAnimationFrame` outside GSAP. |
| INTRO + NAVBAR timing | Navbar must be invisible during INTRO. `initNavbar()` only fires in `initMainExperience()`. |
| SCROLL + CSS `scroll-behavior` | Remove `scroll-behavior: smooth` from CSS. Lenis owns scroll. |
| WEBGL + SCROLL sync | Lenis must use `autoRaf: false`. Three.js adds to GSAP ticker. |
| BACKGROUND + content | Background z-index must stay at 0. Never competes with content. |
| CURSOR on mobile | Disable CinematicCursor entirely on `pointer: coarse` devices. |
| INTRO repeat | Use `sessionStorage` flag — intro runs once per session only. |

## PROJECT MODE ACTIVATION

Project modes (defined in MODES module) override defaults at the token and behavior level.

**To activate a mode:**
1. Load MODES module
2. Set `data-mode="[mode-name]"` on `<html>` element
3. MODES module provides CSS overrides + JS behavior flags

```html
<html data-mode="luxury-cinematic">
```

See `15-project-modes/MODES.md` for all mode definitions.

## AI BEHAVIOR INSTRUCTIONS

When an AI system (Claude, GPT, Gemini, GLM) loads this framework:

1. **Always check which modules are being loaded** — do not apply behavior from unloaded modules.
2. **Never merge modules mentally** — treat each as isolated until MASTER explicitly connects them.
3. **MODES override defaults** — always check if a project mode is active before applying token values.
4. **When in doubt about a visual decision** — consult IDENTITY module.
5. **When in doubt about a value** — consult TOKENS module.
6. **Performance is non-negotiable** — PERFORMANCE module constraints are absolute.
